# Журнал конвективных явлений Якутии

Открытый архив задокументированных смерчей, шквалов, крупного града,
сухих гроз и ливневых паводков в Республике Саха.

**Смысл архива — не полнота, а прослеживаемость.** У каждой записи есть
источник и метка достоверности. Сюда попадает только то, что кто-то
заметил и о чём написали, поэтому по нему нельзя судить о частоте
явлений — но можно проверять прогностические методики на реальных случаях.

## Что где лежит

| Файл | Зачем |
|---|---|
| `index.html` | сам сайт, читает архив из `data/archive.json` |
| `data/archive.json` | все записи, единственный источник правды |
| `scripts/scan_news.py` | ищет кандидатов в новостях, **ничего не добавляет сам** |
| `.github/workflows/scan-news.yml` | запускает поиск раз в неделю |
| `.github/ISSUE_TEMPLATE/new_event.yml` | форма для предложения случая |

## Запуск

1. Создайте репозиторий на GitHub и загрузите эти файлы.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет по адресу `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`

Локально страницу нельзя открыть двойным кликом — браузер запретит читать
JSON с диска. Запускайте так:

    python -m http.server
    # затем http://localhost:8000

## Как добавить случай

Через форму: вкладка Issues → New issue → «Предложить случай в архив».
Затем кто-то из ведущих архив переносит подтверждённое в `data/archive.json`.

Прямо в файл — тоже можно, обычным Pull Request. Формат записи:

```json
{
  "id": "2022-07-04-squall-06",
  "date": "2022-07-04",
  "approx_date": false,
  "cat": "squall",
  "title": "Ураган разрушил стадион на открытии игр",
  "loc": "с. Борогонцы, Усть-Алданский район",
  "detail": "Разрушены трибуны, госпитализированы 18 человек.",
  "sources": ["REGNUM", "Сибирь.Реалии"],
  "cred": "green",
  "added": "2026-08-05",
  "author": "ваш ник"
}
```

Категории: `tornado`, `squall`, `hail`, `thunderstorm`, `flood`, `fire`.
Достоверность: `green` (подтверждено), `yellow` (частично),
`red` (требует проверки).

## Почему поиск новостей не пишет в архив напрямую

Скрипт открывает Issue со списком найденного, а решение принимает человек.
Автоматическая запись выглядит удобнее, но ошибка в ней не видна: ложный
случай попадает в архив, выглядит как настоящий и потом искажает всё, что
на архиве строится. Проверка руками стоит нескольких минут в неделю и
снимает эту проблему целиком.

## Оговорки, которые важно не потерять

- **Смещение наблюдения.** Смерч над Якутском попадёт в новости, такой же
  над пустой тайгой — нет. Плотность записей отражает расселение и охват
  СМИ, а не погоду.
- **Смещение к свежему.** Свежие новости индексируются полнее старых,
  поэтому последние годы всегда будут выглядеть «активнее».
- **Место важнее подробностей.** Запись «Южная Якутия» невозможно сверить
  с моделью. Указывайте село и район, если знаете.
